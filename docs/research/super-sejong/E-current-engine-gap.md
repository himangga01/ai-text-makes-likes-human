## Rulebook–execution mismatch to measure

The quick rules request certain transformations that a route may forbid. For example, `A-18` proposes sentence splitting and `E-1` proposes joining adjacent sentences; `C-2` proposes turning bullet blocks into prose; `I-4` proposes moving an obligation sentence (`vendor/humanize-engine/skills/humanize-korean/references/quick-rules.md:34,48,75,102`). Direct text explicitly forbids sentence split/merge and paragraph movement (`src/engine/rewrite-policy.ts:33`), and checks sentence counts and markers (`src/engine/direct-text-fidelity.ts:268–279`). Office forbids paragraph controls in an edit and now rejects changed sentence counts within each edited block (`engine_runtime/documents/model.py:194–222`; `engine_runtime/super_sejong.py:111–114`). Text files may split or merge sentences under the structural guard but still retain line/Markdown structure (`direct-text-fidelity.ts:182–196`) and face the dropped-content Python gate. The rulebook is therefore a library of *potential* interventions, not an attainable target set for every route. An attainable-rule filter should run before prompting and before measuring success.

## Measurable gap hypotheses

These are hypotheses for a later evaluation, not observations of measured failure rates.

1. **Genre mismatch:** fixed `essay` style comparison over-flags valid reports or misses genre-specific awkwardness. Measure false-warning and improvement rates on a genre-labeled held-out set, holding candidate text constant, against explicit genre routing. Code basis: `engine_runtime/workflow.py:265–266`.
2. **Residual role preservation:** the new `changed_participant_roles()` catches selected overt subject/object swaps with near-identical wording, but recast clauses, zero arguments, comparison targets, and obligation holders may still drift. Create paired counterexamples and measure acceptance by each route; report false acceptance separately from false rejection. Code basis: `super_sejong.py:43–81,111–120`, `workflow.py:263–270`, `documents/model.py:184–222`.
3. **Naturalness localization:** two regex style cues now reach the model with source offsets, but aggregate P1 z-scores and these cues do not identify arbitrary awkward collocations or register shifts for an editor. Annotate sentence spans with native-speaker judgments and compare precision@k of the current two-pattern cues versus broader localized proposals. Code basis: `src/engine/super-sejong.ts:9–40`, `prompt-builder.ts:32–38`, `verify_gates.py:281–297`.
4. **Protection ceiling:** immutable sentences with common numerals, quotations, conditions or modality account for a material share of stylistic issues. Estimate protected-source proportion and human-approved editable proportion by genre before relaxing anything. Code basis: `direct-text-fidelity.ts:38–50,268–291`, `documents/model.py:125–139`.
5. **Cross-chunk consistency:** individually plausible edits can create inconsistent terminology or speech level across chunk/batch boundaries. Measure term/register disagreement per 1,000 sentences before and after; compare with a document-level read-only analysis pass. Code basis: `humanize-engine.ts:490–521`, `documents/workflow.py:54–62`.
6. **Metric calibration:** v2 placeholder baselines and surface signals should not be treated as validated human-vs-AI classifiers. Compare observed feature distributions and confidence intervals on legally usable, matched-genre human and model corpora; evaluate topic/domain leakage. Code basis: `baseline_v2.json:7–22`, `metrics_v2.py:748–806`.
7. **UX interpretability:** actionable, span-linked warnings may help users catch semantic drift better than a generic “review recommended” warning. Measure correction rate and review time in a blinded user study. Code basis: `public/app.js:428–444`, `src/app.ts:270–288`.

## Minimal interfaces for a later engine increment

Preserve the existing conservative acceptance path. The present `StyleFinding` has a rule ID and offsets and enters the text prompt; the present `GateResult` has bounded failure/reason codes. Neither is a calibrated, span-level semantic or naturalness finding. A versioned sidecar would extend those interfaces before any gate-policy change. Suggested boundaries:

```ts
type Genre = 'essay' | 'column' | 'report' | 'blog' | 'abstract' | 'unknown';
interface RewriteContext {
  genre: Genre;             // explicit user choice or unknown, never silently essay
  audience?: string;        // optional and user-provided
  register?: string;        // inferred with confidence, not a rewrite command
  inputKind: 'direct-text' | 'text-file' | 'document';
}
interface KoreanFinding {
  ruleId: string; sourceStart: number; sourceEnd: number;
  category: 'norm' | 'grammar' | 'style' | 'meaning-risk';
  evidence: string; confidence: number; genre?: Genre;
  proposedText?: string; abstainReason?: string;
}
interface CandidateEvidence {
  sourceHash: string; candidateHash: string; findings: KoreanFinding[];
  invariantFailures: string[]; styleDelta?: Record<string, number>;
}
```

For Office, use `{blockId, start, end}` tied to `sourceHash` instead of document-wide UTF-16 positions; keep XML style data local. For files, associate each span with a stable source sentence/paragraph ID so diagnostics survive chunking. A Python or Node adapter could produce a small, bounded JSON `CandidateEvidence` alongside the existing `GateResult` (`src/engine/python-engine.ts:39–50`), and `DocumentEngine` could reuse it after `accept` (`src/documents/document-engine.ts:91–106`). Missing/malformed evidence must mean `unknown`, not a pass.

At first, use findings for evaluation and targeted explanation, not as automatic approval. Promote a rule to automatic gating only after contrast tests show low false rejection on valid Korean, robust detection of meaning drift, and stable performance across genres. A future selector can order candidates by **hard invariants first**, then semantic uncertainty, then genre-conditioned naturalness, retaining source as a valid candidate. The present code already has a safe source fallback (`humanize-engine.ts:393–399`; `documents/workflow.py:106–117`).

## Scope and uncertainty

This audit names what each layer can see from the current working-tree source; it does not benchmark model behavior or the production environment. The implemented Super Sejong components are bounded style hints and conservative surface invariants, with known gaps in semantic interpretation and genre-aware ranking. Any final product claim must use a stabilized code state and actual human-judged results.
