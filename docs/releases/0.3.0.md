# HumanizeKR 0.3.0

DOCX·PPTX의 텍스트를 윤문하고 같은 형식의 새 문서로 저장합니다. 웹 포털·portable Windows 앱·Claude/Codex 스킬이 공통 Python 문서 어댑터를 사용합니다. 원본 문단·표·슬라이드·도형·서식을 재생성하지 않고 허용된 텍스트 노드만 수정합니다.

원본 파일과 기존 출력 파일을 덮어쓰지 않습니다. 숫자·직접 인용·서법·서식 경계·슬라이드 길이 검증을 추가했고, 실패하는 블록은 재시도 후 원문을 유지합니다. 미지원 객체·발표자 노트·각주는 원본을 보존하고 고지합니다. [지원 범위 및 사용법](../documents.md)

## 배포

- `release/HumanizeKR-0.3.0-win-x64.exe`
- `release/HumanizeKR-0.3.0-win-x64-self-signed.exe`
- `release/humanize-kr-claude-0.3.0-win-x64.zip`
- `release/humanize-kr-codex-0.3.0-win-x64.zip`

엔진 핀은 `9747f036cdc28a1a8aea4dc71fef1f7846eb96f7`, Python은 3.14.7, lxml은 6.1.3입니다. Office와 별도 Python 설치 없이 파일을 처리합니다. 모델 실행에는 사용자가 설치·로그인한 Claude 또는 Codex가 필요합니다. 기존 자체서명 인증서를 재사용하며 새 신뢰 루트는 등록하지 않습니다.

## 검증 기록

실제 Codex·Claude 각각 DOCX/PPTX 변환을 실행했습니다. DOCX에서는 짧은 일부 문단의 변경률이 50%를 넘어 1회 재시도 후 해당 문단을 원문으로 유지했으며, 나머지 본문은 윤문했습니다. 숫자와 짧은 인용은 유지했습니다. PPTX는 두 슬라이드의 문장을 윤문하면서 표·도형 서식을 보존했습니다.

두 모델의 DOCX 결과는 Word에서 열어 PDF로 내보낸 뒤 각 1페이지를 확인했습니다. 두 PPTX 결과는 PowerPoint에서 열어 각각 2슬라이드를 PNG로 렌더링하고 확인했습니다. 표·제목·강조의 손실이나 확인된 도형 넘침은 없었습니다. 이 결과는 대표 fixture 검증이며 모든 Office 객체·폰트·문서 레이아웃을 보장하지 않습니다.

실행 로그와 렌더링 중간물은 `runtime/test-tmp/document-live/`, `runtime/test-tmp/document-qa/`에 보관합니다.

최종 자동 검증은 246개 통과입니다: Vitest 193, 문서 Python 23, 기존 Gateway 3, 웹 Playwright 18, packaged Electron Playwright 9. 기존 일반 live/성능 테스트 3개는 별도 조건 때문에 건너뛰었고, 새 문서 실호출은 별도 스크립트에서 두 CLI × 두 형식 총 4건을 완료했습니다. 두 스킬 ZIP은 임시 프로젝트에 두 번 설치해 멱등성을 확인하고 내장 Python만으로 TXT/DOCX/PPTX 왕복을 검증했습니다.

portable EXE를 한글이 포함된 다른 폴더로 복사하고, PATH에서 Node/Python을 제거한 상태의 모의 CLI 실행도 통과했습니다. 사용자 Claude·Codex 스킬은 기존 설치본을 백업하고 0.3.0으로 갱신했습니다.
