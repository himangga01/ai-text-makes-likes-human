# 0.5.4 — 윤문 엔진 2.4.7과 어휘 점검

0.5.3 이후의 변경이다.

## 윤문 엔진

- **기존 엔진을 2.3.2에서 2.4.7로 올렸다.**
  - 원본은 `epoko77-ai/im-not-ai`의 커밋 `c07df14`다. 이전 핀 `9747f03` 이후 113개 커밋이다.
- **어휘 점검을 넣었다.**
  - 원문에서 한국어 독자가 읽다가 걸리는 표현을 어휘 사전(115개)으로 찾는다. 예를 들면 "~의 렌즈로 보면", "결을 더하다" 같은 표현이다.
  - 찾은 항목은 첫 윤문 요청에 점검 목록으로 함께 보낸다. 항목마다 바꿀 때·둘 때·바꾸는 방식이 있고, 모델은 문맥을 보고 판단한다. 일괄 치환하지 않는다.
  - 보수적 재시도와 후보 재검토에는 보내지 않는다.
  - 직접 입력의 개념 보존 검사는 원문 명사가 결과에 남아야 통과한다. 그래서 "세 가지 렌즈로"를 "세 가지 관점에서"로 바꾸면 첫 시도가 버려지고 보수적 재시도로 넘어갔다(실측: 모델 호출 2회, 26.7초). 어휘 점검이 원문에서 한 단어로 찾은 명사(렌즈·층위·기둥 등)만 이 검사에서 뺀다. [조건부] 항목의 명사는 원문에서 두 번 이상 쓰였을 때만 뺀다. 구 단위 항목의 명사("미묘한 접근"의 접근), 더 긴 단어 안의 일치(콘택트렌즈), 따옴표 안의 표현은 그대로 보호한다.
- **어휘 복원을 넣었다.**
  - 윤문이 원문 문서 어디에도 없던 '바꿈 우선' 표현(61개)을 새로 만들면, 그 문장을 원문 문장으로 되돌린다.
  - 되돌린 문장이 있으면 결과 화면에 `LEXICAL_RESTORED` 안내가 나온다.
  - 문장 순서가 바뀌었거나, 되돌리면 같은 문장이 두 번 나오면 되돌리지 않는다. 원본 2.4.7은 이 경우 한 문장을 지우고 다른 문장을 두 번 남겼다. 포털 패치로 막았다.
  - 후처리 순서는 서법 복원 → 쉼표 정리 → 어휘 복원 → 조사 교정이다.
  - 어휘 점검과 복원이 실패해도 윤문을 막지 않는다. 실패는 건수로만 남긴다.
- **원본의 검사 수정도 함께 들어왔다.**
  - 순수 '하였'체 원문에서 문장을 나눌 때 늘어나는 '하였'을 격식 상향으로 보지 않는다. 새로 생긴 문장 수까지 허용한다.
  - "보완 필요."처럼 '요'로 끝나는 명사 종결을 해요체로 세지 않는다. 구어체가 사라졌다고 잘못 보고 결과를 되돌리던 일이 줄어든다.
  - 당위 표현 검사가 "분야 해설서" 같은 명사 뒤 '해-'를 당위로 세지 않고, "있어야 해요" 같은 해요체 당위는 놓치지 않는다.
  - 쉼표가 3개보다 적은 글은 쉼표 구간 길이로 문체 목표 달성을 판정하지 않는다.
  - 경로 판단이 "요약하면·요컨대" 같은 결산 표현과 "첫째·둘째" 열거를 센다.
- 줄바꿈(LF·CRLF)은 어휘 점검·복원에서도 그대로 둔다.

## 스킬

- 두 윤문 스킬도 같은 어휘 점검과 어휘 복원을 쓴다.
  - 파일 경로는 첫 시도에 어휘 점검 파일(`lexicalHintsPath`)을 받는다.
  - 강도 경로는 같은 블록이 지시문에 들어간다.

## 적용하지 않은 곳

- Office 문서(DOCX·PPTX)와 슈퍼세종엔진 v2에는 적용하지 않았다. 슈퍼세종엔진이 원본에서 옮겨 온 코드는 2.4.7에서 바뀌지 않아 그대로 둔다.

## 올릴 때

- 서버 준비 검사가 엔진 라벨 2.4.7을 요구한다. vendor 파일과 `npm run build` 결과를 함께 반영하고 재시작한다. 한쪽만 바뀌면 서버가 "준비 안 됨"으로 표시된다.
- 엔진이 바뀌기 전에 시작한 스킬 작업은 다음 단계에서 엔진 변경으로 거절된다. 새 작업으로 다시 시작한다.
- macOS에는 PowerShell이 없어 `scripts/sync-engine.ps1`을 실행할 수 없다. 이번 갱신은 같은 파일 목록을 손으로 스테이징하고, 새 패치를 적용한 결과가 vendor 트리와 같은지 비교했다.
